Проверь тестовое покрытие текущих изменений по правилам `CLAUDE.md`.

**Scope:** `git diff HEAD` (uncommitted: staged + unstaged). Если нужен
контекст ветки — `git diff origin/main...HEAD`.

Для каждой новой/изменённой бизнес-логики проверь:

1. **Покрытие.** Есть ли тесты на граничные случаи? Перечисли конкретные
   непокрытые кейсы: пустой/невалидный ввод, границы диапазонов, ошибки сети
   и таймауты, null/undefined, конкурентные вызовы, offline, миграции данных.
2. **Качество тестов.** Assertions не ослаблены, моки не подогнаны под бажный
   код, нет `skip`/`xfail`/пустых `expect` без причины.
3. **Детерминизм.** Тесты не зависят от реальных внешних сервисов, времени,
   порядка выполнения и общего состояния.
4. **Что assert'ится.** Тесты проверяют поведение и контракты, а не
   внутреннюю реализацию (иначе любой рефакторинг их ломает).
5. **Реальный прогон.** Если тесты можно запустить — запусти их и приведи
   результат. «Тест существует» ≠ «тест проходит».

Формат вывода:

- `[MISSING]` `file` — непокрытые edge cases (перечисли кейсы)
- `[SUSPECT]` `file:line` — ослабленный assert, подогнанный мок, недетерминизм
- `[FAIL]` `file` — тест существует, но падает (с выводом ошибки)
- `[OK]` — что покрыто корректно

Если изменённый код — не бизнес-логика (конфиги, docs, стили) — ответь одной
строкой «Тесты не требуются».

В конце предложи следующий шаг: «Могу сгенерировать недостающие тесты —
скажите, для каких кейсов».
